# fsmjs inspector

Посмотреть на автомат.

[**Открыть инспектор**](https://evgkch.github.io/fsmjs/inspector/) · [in English](README.md)

Граф автомата — это проекция самого автомата: `JSON.stringify` сохраняет метки и вместо кода
каждой операции пишет её имя. Оставшегося хватает, чтобы автомат нарисовать, проверить — и, хотя
операций в нём уже нет, всё равно запустить. Инструмент делает эту фразу пригодной к работе.

## Фигура

Правило — это точка `(from, on, to, emit)`, четыре дискретные координаты, а четырёхосных рисунков
не бывает. Вместо этого — три блока вокруг двух общих индексов:

```
            ┌─────────────┐
            │  TO × EMIT  │  3 — по этой линии общие столбцы
   ┌────────┼─────────────┤
   │FROM×ON │  FROM × TO  │  1 и 2 — по этой общие строки
   └────────┴─────────────┘
```

**1** — область определения δ: строка это состояние, столбец — тип события, а одна ячейка это одна
пара `(q, σ)`, та самая, которой адресован `dispatch`. **3** — область значений, `(r, λ)`. У
правила, которое ничего не испускает, ячейки там нет — нет выхода, из чего её сделать, — поэтому
его называет имя столбца. **2** — то же отношение, спроецированное вдоль Σ и Λ, так что его
ячейки это *множества* правил: одну пару состояний может соединять несколько событий.

1 и 3 — две половины перехода. У библиотеки для них есть собственные слова: **причина** (`source`
и `input`) и **следствие** (`target` и `output`), и ни одна не является началом больше другой.
Наводите на ячейку любой из них — из неё выходят две полосы до имён на обеих осях, та, для которой
у блока 2 есть ось, продолжается через него, и загорается то, чем может оказаться вторая половина.
Нажатие закрепляет половину, второе нажатие берёт правило. Блок 2 — только показ, никогда не
управление: наведите на пересечение, и загорятся все `ON`, которыми правила оттуда выходят, и все
`EMIT`, с которыми они приходят. Пересечение — не то, что выбирают.

Сверх схемы рисуется ровно то, чего в ней нигде не написано: каких состояний не достигает ни один
прогон, из каких ничего не выходит, какие пары связаны, но не одним правилом, и какие правила
`validate` считает несрабатывающими. Второго вида нет и третьего тоже: `toRules`, `toTree`, `toDot`
и `formatIssues` пересказывают схему другими словами, а схема и так открыта слева. Фигура нужна
затем, чего ни один из них не скажет: где машина стоит, что она может оттуда, и что уже сделала.

## Два способа работы

При выключенном флаге **explore** автомат где-то стоит: `FROM` — там, где он, и двигается вместе с
ним; всё, куда он не дотянется, погашено и не отвечает даже на наведение; названные обе половины
перехода означают, что переход сделан. При включённом — текущего состояния нет, вся схема
доступна, и ничего не срабатывает: двигать нечего.

## Что он читает

Схему в JSON — вставьте свою или возьмите одну из готовых. Их шесть, и три написаны не руками: это
`JSON.stringify` тех машин, на которых работает сам инструмент, и `npm run dump` переписывает их
перед каждой сборкой. Откройте «the inspector's choice» — и фигура нарисует то, что решало, как
фигура себя ведёт, пока вы по ней водили.

Условие, прочитанное обратно из JSON, — это имя, а не код, поэтому дамп потерял единственное, чем
два правила одной ячейки различаются. Инструмент возвращает его на место: каждое правило собирается
с условием, которое спрашивает, его ли вы назвали, — так что ваше второе нажатие и *есть* условие.
`with` по-прежнему читается как тождество, поэтому контекст остаётся каким был. Машина, которую вы
двигаете, настоящая от начала до конца, и в этом весь смысл.

## Работающий автомат

Инспектор — это приложение, которое вы запускаете, а отлаживаемое приложение пишет одно слово.

```sh
npm install
npm run inspect      # инспектор и реле, которое он слушает
```

Дальше — в отлаживаемом приложении, столько автоматов, сколько их там есть:

```ts
import { inspect } from "@evgkch/fsmjs-inspector";

const cart = inspect(new StateMachine(schema, start), { name: "cart" });
inspect(upload, { name: "upload", description: "повторы и когда сдаётся" });
```

`inspect` возвращает тот же автомат — это функция тождества со слушателем внутри, поэтому её
пишут вокруг уже существующего экземпляра и убирают удалением одного слова.

Откат прогона из окна инспектора включается тем, что вы отдаёте ему уже собранный рекордер:

```ts
import { history } from "@evgkch/fsmjs/debug";

const past = history(cart);
inspect(cart, { name: "cart", history: past });
```

Экземпляр здесь — и разрешение, и сам факт. Флаг означал бы, что инспектор сам вызовет
`history(cart)`, — и тогда строчка, которой отладчик выключают, заодно убирает рекордер, на
котором держалось ваше undo; а приложение, которое уже пишет историю, писало бы её дважды.
Отдайте то, что построили сами, — и удаление вызова оставит построенное ровно там, где оно было.

Каждый автомат называет себя сам, поэтому сверху в инспекторе — список тех, кто вышел на связь, и
вы выбираете; `?ws=ws://host:port` направит его к реле на другом хосте. У точки входа, которую
импортирует приложение, нет ни строчки про документ и она не тянет стилей: там, за кем смотрят, DOM
может не быть вовсе, и серверу незачем тянуть страницу ради того, чтобы рассказать о своём автомате.

Одна копия `@evgkch/fsmjs` в приложении — единственное жёсткое требование: библиотека вынесена из
сборки нарочно, потому что вторая копия — это второй символ `TRANSITION`, и слушатель не сработает
никогда.

Фигуру можно положить и прямо на отлаживаемую страницу, а не в отдельное окно: `overlay(fsm)` из
`@evgkch/fsmjs-inspector/ui` вместе с `@evgkch/fsmjs-inspector/style.css`. Рекордер он принимает
тем же способом — `overlay(cart, { history: past })`, — а годится ровно тогда, когда фигуру хочется
видеть на той же странице, которую вы отлаживаете: он рисует, поэтому стоит таблицы стилей.

По проводу идут имена: схема — как её пишет `JSON.stringify`, и четыре типа каждого перехода.
Никакого контекста и никакой нагрузки: данные приложения из него не уезжают, а контекст, который
нельзя сериализовать, перестаёт быть проблемой.

Удалённый subject умеет ровно то, что отдало приложение, и ничего сверх: `drive` нет — посылать
событие в чужой процесс этому переходу пока не разрешено; `rewind` — только если приехал `History`.
Это и есть весь режим «только чтение»: не флаг, а отсутствие, и все части инструмента и так
спрашивают.

## Запуск

```sh
npm install
npm run dev
```

`npm run build` кладёт статический сайт в `dist/`: `npm run dump` обновляет схемы, которые
инструмент хранит о самом себе, `tsc --noEmit` — ворота, дальше `vite build`. `npm run build:lib`
собирает пакет в `dist-lib/`: одно слово для приложения, инструмент, который рисует, и стили.

## Раскладка

```
index.html     отдельная страница
viewer.html    инспектор: смотрит за автоматами в другом месте
src/           сам инструмент
schemas/       на что его можно навести, включая его собственные машины
scripts/       dump.mjs пишет три из них · relay.mjs держит провод
```

Внутри `src/` слои идут в одну сторону: `shared` → `entities` → `features` → `widgets` → `pages` →
`app`. Шов, на котором всё держится, — `entities/machine`: `Subject` это то, что фигуре нужно знать
о машине, и это всё; реализаций три — дамп в редакторе, машина в этой же области видимости и машина
на том конце провода. Всё, что помнят, — автоматы самой библиотеки: что удерживается и где
указатель, какой режим, что редактор делает со словом, как разложена страница, за каким из
удалённых автоматов сейчас смотрят. Все они — та самая библиотека, работающая в инструменте,
который её объясняет.
